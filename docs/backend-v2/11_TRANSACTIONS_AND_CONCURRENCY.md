## 1. CONCURRENCY & TRANSACTION DESIGN PRINCIPLES

1. **Optimistic Concurrency Control (`version` Column):**
   - Both `IndividualApplication` and `CollectiveApplication` carry `version Int @default(1)`.
   - Every mutating command requires `expectedVersion` in the request DTO and executes an atomic conditional update:
     ```ts
     const updated = await tx.collectiveApplication.updateMany({
       where: { id: appId, version: expectedVersion, workflowStatus: { in: allowedStatuses } },
       data: { ...changes, version: { increment: 1 } },
     });
     if (updated.count === 0) throw new AppError(409, 'WORKFLOW_VERSION_CONFLICT', ...);
     ```
2. **Idempotency Keys (`Idempotency-Key` Header):**
   - State-transition POST endpoints (`submit`, `forward-to-city`, `assign`, `supplements`, `review/complete`, `committee/decision`, `publish-batch`, `evidence/finalize`) accept an `Idempotency-Key` UUID header.
   - The key is recorded on `AuditLogEvent.idempotencyKey` (`@@index([idempotencyKey])`). Retrying a request with the same key and actor within 24 hours returns the original success outcome without duplicating rows.
3. **Zero External I/O Inside Database Transactions:**
   - Object storage calls (`HeadObject`, presigned URL signing) always execute *outside* `prisma.$transaction` so database locks are held for `< 25 ms`.
